# Локальная разработка

Пакет запускается из своего корня на Python 3.11+. Для ядра не нужны внешние runtime-библиотеки, реальные аккаунты или сетевые ключи.

## Демонстрация

```sh
PYTHONPATH=src python3 -m otmetki_core demo
PYTHONPATH=src python3 -m otmetki_core serve
```

Сервер доступен только по `http://127.0.0.1:8088`. Остановить его можно `Ctrl+C`. Файл `.data/demo.sqlite3` содержит локальную демонстрационную базу; его не следует добавлять в исходники.

`demo` создаёт два вымышленных курса, тему, лекцию, семинар, глоссарий, самостоятельную работу без даты и пример правила баллов. Идентификаторы генерируются заново. Если предметы уже существуют, заполнение пропускается. Для отдельного эксперимента используйте новый файл:

```sh
PYTHONPATH=src python3 -m otmetki_core --database .data/experiment.sqlite3 demo
PYTHONPATH=src python3 -m otmetki_core --database .data/experiment.sqlite3 serve --port 8089
```

Команда `init` только создаёт базу и применяет миграции:

```sh
PYTHONPATH=src python3 -m otmetki_core --database .data/empty.sqlite3 init
```

## Проверка API

```sh
curl --fail http://127.0.0.1:8088/api/courses?direction=management
```

После чтения списка материалов курса можно выбрать их в интерфейсе и скачать TXT. Для командного экспорта подставьте настоящие идентификаторы из своей вымышленной базы:

```sh
PYTHONPATH=src python3 -m otmetki_core context MATERIAL_ID --output .data/context.txt
```

CLI-команда `context` выбирает текущие версии. Для явно фиксированных версий используйте библиотеку или `POST /api/context.txt` по [контракту](api.md).

## Тесты

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

Для проверки записи удобно использовать `Store(":memory:")`. HTTP демонстрация требует файловую базу: новое соединение создаётся для каждого запроса, поэтому отдельная in-memory база там запрещена.

При изменении поведения проверяйте:

- Отказ при неверных полях и типах; неотрицательные конечные баллы и даты с часовым поясом.
- Связи курса и темы, раздельные направления и уникальность курса.
- Создание следующего снимка, неизменность старого текста и конфликт устаревшей правки.
- Сохранение источников после удаления повторов; отличающиеся числа и условия должны остаться.
- Отказ контекста из разных курсов, корректность TXT и ограничений.
- Loopback-привязку, Host/Origin и безопасные ошибки локального сервера.

Не пишите тесты на реальных студенческих файлах. Материалы примеров — это короткие самостоятельно составленные тексты, а не расписание или готовые работы пользователей.

## Изменение схемы

Не редактируйте применённую миграцию. Добавьте следующий файл, например `002_example.sql`, обновите модель и [документацию](data-model.md), затем проверьте:

1. Создание базы с нуля.
2. Переход с предыдущей схемы без потери записей.
3. Повторное открытие уже обновлённой базы.
4. Откат транзакции при ошибке и обнаружение изменения контрольной суммы.

Обратного автоматического отката миграций в текущем пакете нет. Для эксперимента используйте отдельный файл базы, а не рабочее хранилище другого приложения.

## Встраивание

`Store` рассчитан на отдельное SQLite-соединение; не передавайте один экземпляр между потоками. Используйте короткий контекстный менеджер, как в README. Приложение должно проверить права до вызова библиотечных функций и API, а не только скрыть ссылки в интерфейсе.

При добавлении нового адаптера документируйте источник подготовленного текста и сохраняйте страницу, слайд, область применения и предупреждения, когда они известны. Не отмечайте непроверенный текст как безошибочный. Интеграции распознавания и ИИ не следует описывать как существующие функции этого пакета.

## Проверенный экспорт исходников

`public-files.json` перечисляет каждый разрешённый файл явно. Экспортёр не копирует весь каталог и не переносит Git-историю. Изолированный новый каталог задаётся вручную:

```sh
python3 tools/export_public.py --output ../core-source-export
```

Экспорт включает `release-manifest.json` с SHA-256 каждого проверенного файла. Записываются именно проверенные байты; изменения исходника после сканирования не подменяют снимок. Неизвестные файлы, базы, двоичные материалы, локальные настройки и символьные ссылки не включаются.

При подготовке публикации можно передать `--deny-list` с отдельным приватным JSON-массивом запрещённых строк; список не копируется. Сканер ищет распространённые ключи, email, адреса, служебные пути и непроверенные URL. Это дополнительная проверка, а не доказательство отсутствия любых личных сведений. Авторство новой Git-истории, изображения и настройки публикуемого репозитория проверяются отдельно. Экспорт сам ничего не публикует.

## Проверка приложения

В `app` выполните `npm ci`, `npm run typecheck`, `npm test`, `npm run test:client`, `npm run build`. Python worker: из app/server выполните `../.venv/bin/python -m unittest test_extract.py`. Fixtures синтетические, базы создаются во временных каталогах. Проверки покрывают подпись Telegram, изоляцию пользователей и аудиторий, версии, отзыв доступа, альтернативы, модерацию, архив и потоки ответов. Реальные файлы и ключи не нужны. Для демонстрационных материалов используйте `npm run demo`.
